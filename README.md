# 每日新聞監測

半自動流程：**自動撈候選 → 你人工挑選 → 一鍵排版成給客戶的報告**。
產出的報告就是可以直接複製貼到 Email／LINE 的純文字。

## 每天的三個動作

```bash
./monitor fetch                 # 1. 撈全部客戶的當日候選 → candidates/
./monitor judge                 # 2. 以 Codex Luna 判讀候選（排程會自動執行）
                                # 3. 在 Obsidian 打開候選檔勾選／刪除／補記者名
./monitor build                 # 4. 排版成報告 → reports/，同時印在終端機可直接複製
```

`fetch` 也會讀取 `defaults.yaml` 指定的 Excel 人工搜尋表。Google 連結會使用
超連結中的實際搜尋式；工商時報、經濟日報站內搜尋會轉成限定網站的新聞搜尋，
並要求標題包含搜尋詞。廣泛的產業搜尋結果會留在候選清單並註明
「Excel 搜尋」，預設不勾選，由人判斷是否適合客戶；若標題未命中主題詞，
正文須至少提及兩次才會留下。沒有篇數上限。Excel 裡尚未建立客戶設定的
搜尋會列出提醒，不會擅自建立客戶或寄送報告。更換表格用 `--workbook PATH`，
暫時停用用 `--no-workbook`。同一天重跑會保留已有候選檔與人工修改；確定要
重建時才用 `--overwrite`。

`judge` 只對候選檔裡尚未註記的連結下載正文前段（最多 2,200 字）與署名線索，
存到不進 Git 的 `.state/article-excerpts.json`，交給用 ChatGPT 訂閱登入的
Codex CLI，以 `gpt-6-luna` 判斷是否為新聞、是否與候選客戶相關、記者是誰。
同一篇多家客戶只判讀一次，結果快取 30 天；第二、三輪只處理新連結。
不相關或非新聞會取消預設勾選並留下 AI 註記；標題提到客戶公司名的新聞
保留原勾選狀態，加註「請確認」。站內搜尋頁不適用這項保留規則。
相關新聞保留原本勾選狀態；
記者欄已有人工內容時不覆寫。判讀失敗時保留原本規則供人工確認。
抓不到正文的連結也保留原規則，下輪再試。
總覽信會略過 AI 判為非新聞或不相關的未勾選項目；標題提到客戶公司名
（站內搜尋頁除外）或人工重新勾選的項目仍會寄出。

此專案的 Codex CLI 安裝在 `.state/codex-cli/node_modules/.bin/codex`。
執行該指令的 `login` 並以 **ChatGPT 帳號**登入；用 `login status` 確認。
`judge` 只接受顯示 ChatGPT 登入的 CLI，
並清除 `OPENAI_API_KEY` / `CODEX_API_KEY` 等環境變數後啟動，避免意外走
另計費的 API key。更新 CLI 可用
`npm install --prefix .state/codex-cli @openai/codex`。
Codex CLI 在本機執行流程，Luna 判讀仍經由網路送往 OpenAI，並非離線模型。

### 寄一封 20 家候選總覽到自己的信箱

將 `.env.example` 複製成 `.env`，填入 SMTP 主機、埠號、SSL 或 STARTTLS、
SMTP 帳號與應用程式密碼，以及 `MAIL_FROM`、`MAIL_TO`。`.env` 已加入
`.gitignore`，建議權限設為 `600`。Gmail 可用 `smtp.gmail.com:465` 和
`SMTP_SECURITY=ssl`；密碼使用應用程式密碼。

```bash
./monitor email --dry-run          # 產生 .state/email-preview-<日期>-all.txt，不寄送
./monitor email                    # 寄一封含 20 家所有候選的純文字信
./monitor email --checked-only     # 只寄預設勾選的候選
```

郵件每家以「乙公司【 9/28 新聞監測】」形式分段，逐則列出媒體、記者、
標題與原文連結；不顯示候選檔的勾選狀態，不含新聞全文，也不會把候選
當成已發給客戶的報告。已被 AI 判為非新聞或不相關且未被人工重新勾選的項目
不會寄出。寄出後會在 `.state/`
記錄日期與郵件 ID，避免同一天同模式誤寄兩次；確定要重寄才加 `--resend`。

只跑一家：`./monitor fetch client-a`、`./monitor build client-a`。

## 自動排程（上班日）

Google News 每次回傳的結果會小幅變動，所以每天分三輪搜尋：crontab 在
02:00 執行 `./scheduled.sh first`，05:00 執行 `./scheduled.sh second` 並寄
候選總覽信，07:30 執行 `./scheduled.sh third` 再寄一次（主旨標「更新版」）。
是否為上班日依人事行政總處行事曆判斷（國定假日跳過、補班日照跑），紀錄在
`.state/logs/<日期>-<輪次>.log`。

每輪都用 `./monitor fetch --merge`：候選檔不存在就新建，已存在就只把新撈到
的新聞依媒體排序（`source_order`，工商第一、經濟第二）插進去，並標「HH:MM
補進」；人工勾選、排序與刪除都保留，刪掉的新聞不會被補回來。
每輪抓取後執行 `./monitor judge`，05:00 與 07:30 的候選總覽信會在判讀後寄出。

### 放假期間的新聞會自動補上

`fetch` 的涵蓋範圍是**從上一個上班日 00:00 到現在**，不是固定一天，所以：

| 跑的日子 | 自動涵蓋 |
|---|---|
| 一般平日（週二～週五） | 前一個上班日 ＋ 今天 |
| 週一 | 上週五、六、日 ＋ 今天 |
| 連假後第一天（例如 10/12） | 10/08 起共四天 |
| 春節後第一天（例如 2/19） | 2/13 起共七天 |

判斷依據是人事行政總處的「政府行政機關辦公日曆表」（第一次執行會自動下載，存進
`.state/calendar-<年>.json`），所以國定假日、彈性放假、補班的週六都算得對。
執行時會印出實際涵蓋範圍，候選檔第二行也會寫著。

想自己指定範圍：`--days 5`（往回五天）或 `--since 2026-09-18`（從某天 00:00 起）。
臨時停更幾天回來補件，用 `--since` 最直接。

### 候選檔長這樣（`candidates/2026-09-21-client-a.md`）

```markdown
- [x] 工商時報｜王小明｜甲公司新藥上市 營運添動能
  https://www.ctee.com.tw/news/20260918701187-430504  <!-- 09/18 16:00 -->
```

- `- [x]` 會進報告，不要的**整行刪掉**或把 `x` 改成空白。
- 欄位是 `媒體｜記者｜標題`，抓不到記者時是空的，直接手打補上。
- **順序可以自己搬動**，報告會照候選檔的順序輸出。
- 上次報告送過的連結會自動變成未勾選並註記「已送過」，不會重複寄。

### Google 沒撈到的新聞

貼網址就好，會自動補齊媒體、記者、標題並加進今天的候選檔：

```bash
./monitor add client-a https://www.ctee.com.tw/news/…
```

### 報告長這樣（`reports/2026-09-21-client-a.md`）

```
甲公司【 9/21 新聞監測】

1.工商時報 杜蕙蓉
甲公司新藥上市 營運添動能
https://www.ctee.com.tw/news/20260918701187-430504
```

## 新增客戶

複製 `clients/_template.yaml` 成 `clients/<英文代號>.yaml`，填 `name` 和 `queries`
（公司名、英文名、產品名、高層姓名各一行）。`./monitor clients` 可列出目前有誰。
不帶客戶參數時，`fetch` / `build` 會一次跑完所有客戶，各出各的報告：

```bash
./monitor fetch          # 甲公司、乙公司… 全部撈完，各自一個候選檔
./monitor build          # 各自一份報告
```

### 二十家客戶也是同一個指令

`fetch` 走共用管線：所有客戶的關鍵字先去重，Google News 只查一次；同一則新聞的
網址還原和記者名也只抓一次，再依關鍵字分派給各家客戶。實測 20 家客戶：

| 情況 | 耗時 |
|---|---|
| 冷啟動（無快取） | 約 70 秒（45 組關鍵字、413 則新聞去重成 326 則） |
| 當天再跑一次 | 約 5 秒（網址與記者名走快取） |

快取放在 `.state/urlcache.json`、`.state/reporters.json`、`.state/bodyhits.json`
（後兩者保留 90 天），
所以同一則新聞被多家客戶撈到時只會抓一次。連線數預設 8，可用 `--workers` 調整。

多客戶時 `fetch` 會多產一份 **候選總覽**
（`candidates/_總覽/<日期> 候選總覽.md`），依待處理量排序，沒新聞的客戶列在最後：

```markdown
| 客戶 | 候選 | 預設勾選 | 涵蓋範圍 | 清單 |
|---|---|---|---|---|
| 甲公司 | 35 | 35 | 09/18（五） 起 | [[2026-09-21-client-a]] |
| 乙公司 | 12 | 6 | 09/18（五） 起 | [[2026-09-21-client-b]] |

> 今天沒有候選新聞的客戶：昱厚、合一生技
```

早上從這份開始，點進去勾選，勾完 `./monitor build` 一次產出全部。多客戶時 `build`
只印摘要（哪家幾則、誰缺記者名、誰沒東西），要看某家全文就 `./monitor build <客戶>`。

每家客戶可以不一樣的地方：

| 設定 | 用途 |
|---|---|
| `numbered` | 報告要不要編號。甲公司是 `1.` `2.`（預設 true），乙公司不編號（設 false） |
| `queries` | 丟進 Google News 的搜尋字。集團客戶記得把關係企業放進來（乙公司收了子公司） |
| `core_keywords` | 判斷「這則到底關不關這家客戶」用的字，通常比 `queries` 短 |
| `relevance` | 怎麼判斷一則新聞關不關這家客戶，見下表 |
| `topic_keywords` | 產業關鍵字。不是自家新聞、但確實在談這些主題的也收進來 |
| `check_offtopic` | 通過篩選的全部預設勾選（含產業新聞）。丙公司用這個 |
| `holidays` / `extra_workdays` | 這家客戶自己的休假日 |

### relevance：三種篩選強度

公司名越通用，Google News 越會撈到無關新聞（實測兩字的公司名會撈到香港新聞、足球、建案）。

| 設定 | 行為 | 適合 |
|---|---|---|
| `off` | 全部收進來、全部預設勾選 | 甲公司：連沒提到公司名的產業政策新聞都要收 |
| `title` | 標題沒提到 `core_keywords` → 留在清單但取消勾選 | 想自己掃過一遍再決定 |
| `body` | 標題沒提到 → 再讀**正文**；正文有提到就留著（取消勾選、註明「內文有提到」），正文也沒有就直接不收 | 其餘 18 家 |

被留下來的產業新聞會註明命中了哪個主題字、出現幾次，例如
`<!-- 產業新聞：外泌體×20 -->` 一看就知道是專題報導，
`產業新聞：幹細胞×1` 多半是側欄漏進來的，刪掉就好。

想順便監測產業動態的客戶（例如丙公司要追外泌體、再生醫療），
在 `topic_keywords` 列主題字即可：自家新聞自動勾選、確實談到該主題的留著不勾、
其餘不收。實測「外泌體＋再生醫療」7 天撈到 99 則，濾完剩 37 則全是相關產業新聞
（酪梨、小巨蛋、央行那種語意誤撈的都被擋掉）。

`body` 只比對文章正文段落，不看側欄的「相關新聞」——否則 udn 的推薦列表會讓
每則財經新聞都「提到」客戶。實測某客戶 15 則 → 4 則、
另一家 7 則 → 1 則，被濾掉的都是真的沒提到。

## 想調整輸出時改哪裡

| 想改什麼 | 改哪個檔 |
|---|---|
| 媒體顯示名稱（例如 `鏡週刊` 要叫 `鏡新聞`） | `defaults.yaml` 的 `media_names` |
| 過濾盤後數字、討論區等雜訊 | `defaults.yaml` 的 `exclude_keywords` |
| 排除境外媒體（預設擋 .hk/.cn/.mo 等） | `defaults.yaml` 的 `exclude_domains` |
| 報告裡媒體的排列順序 | `defaults.yaml` 的 `source_order` |
| 標題格式 `甲公司【 9/21 新聞監測】` | 客戶檔的 `report_title` |
| 這家客戶專屬的關鍵字／排除字 | `clients/<客戶>.yaml` |
| 公司自己的休假日（例如尾牙、彈性假） | 客戶檔的 `holidays: ["2026-01-30"]`／`extra_workdays: []` |

客戶檔的設定會疊加在 `defaults.yaml` 上（清單是相加，不是取代）。

## 檔案結構

```
monitor              指令入口（fetch / add / build / tidy / clients）
defaults.yaml        共用設定：資料夾結構、媒體名對照、雜訊字、媒體排序
clients/*.yaml       每個客戶一個檔

candidates/<客戶>/<年-月>/<日期>-<客戶>.md    每天的候選清單（人工勾選的地方）
reports/<客戶>/<年-月>/<日期>-<客戶>.md       最後要給客戶的報告
reports/<客戶>/<客戶名>報告索引.md            自動更新，列出每天幾則＋連到報告

.state/              已送過的連結紀錄、網址還原快取、行事曆
bin/                 Python 腳本（用 uv 執行，依賴自動安裝）
```

一家客戶一個資料夾、一個月一層，所以每個資料夾大約 20 個檔，Obsidian 裡好翻。
`build` 每次都會更新該客戶的**報告索引**，要回頭查「上個月哪幾天發了幾則」看那份就好。

資料夾結構寫在 `defaults.yaml` 的 `paths`，想改成別的分法（例如年在前、或全部平放）
就改樣板，然後跑 `./monitor tidy` 把既有檔案搬過去。

候選檔是過程檔，報告才是交付物。累積太多時：

```bash
./monitor tidy --prune-candidates 60        # 先列出 60 天前的候選檔
./monitor tidy --prune-candidates 60 --yes  # 確認後才真的刪
```

## 已知限制

- 來源是 Google News 台灣索引，**不保證每則都撈得到**（紙本獨家、部分付費牆文章常缺）。
  漏的用 `./monitor add` 補。
- 記者名是盡力抓（JSON-LD、內文「記者XXX」）；抓不到就留空給你手動填。
- Google News 標題偶爾會吃掉空白，需要時在候選檔直接改標題。
- 上一個上班日當天的新聞會整天重抓一次，但已經送過的連結會自動標「已送過」並取消勾選，
  所以不會重複寄給客戶。
- 每次 `fetch` 會連到各新聞網站抓記者名，約 10～20 秒；想快一點加 `--no-reporter`。

## 環境

需要 `uv`（已安裝）。第一次執行會自動裝好 Python 依賴，不用另外建虛擬環境。
